# Предметная область

Наша информационная система — платформа для сбора, хранения и агрегации отзывов студентов о преподавателях Университета ИТМО. Система ориентирована на сферу образования и помогает студентам выбирать преподавателей под свои интересы и цели.

# Цели информационной системы

Система покрывает полный цикл работы с данными:

1. Автоматизированный сбор информации о преподавателях (ФИО, табельный номер, фотография) из открытых источников и сохранение в единой базе данных.
2. Возможность студентам оставлять комментарии и выставлять оценки по параметрам, заданным системой.
3. Удобные инструменты поиска, фильтрации и анализа собранной информации.

# Роли и права

* **Пользователь:** поиск, просмотр карточек и отзывов. Добавление/редактирование/удаление своего отзыва, добавление новых тегов.
* **Администратор:** управление тегами, удаление отзывов, блокировки, агрегированные отчёты.

# Функциональные требования

## 1. Главная страница

    1.1. Содержит название и описание информационной системы.

    1.2. Кнопки перехода на страницу поиска и страницу оценивания (для авторизованного пользователя) и кнопки регистрации/входа (для неавторизованного пользователя).
 
    1.3. Кнопка перехода на страницу с дашбордами (только для администраторов).

    1.4. Если пользователь в бане, на странице указано уведомление об этом (доступ к другим страницам пользователь не имеет).

## 2. Страница поиска

    2.1. Должна содержать строчку поиска по ФИО. Поиск должен производиться по любой из частей ФИО.

    2.2. Должна содержать выпадающий список фильтрации по тегам. 
    
    2.2.1. Напротив каждого тега нужно указывать количество людей, которым этот тег принадлежит.

    2.3. Все используемые теги должны быть указаны под строчкой поиска с крестиком (т.е. с возможностью удаления).

    2.4. Результаты поиска в отображаются в виде карточек. Карточка содержит фотографию, ФИО, табельный номер, средний рейтинг и теги преподавателя.
    
    2.4.1. Eсли теги не вмещаются в карточку, должна быть отображена только часть из них.

    2.4.1.1. Должно быть отображено количество тегов, которые не поместились в карточку.

    2.5. Максимальное количество карточек на странице - 40 штук.

    2.6. Снизу страницы должна быть пагинация со следующими кнопками: вперед и назад.

    2.7. Также должно быть отображение текущей страницы (с возможностью ручного ввода для смены страницы) и отображением максимального количества страниц.

    2.8. При нажатии на карточку должен производиться переход на страницу с отзывами.

## 3. Страница с отзывами

    3.1. Фото, ФИО, общий средний рейтинг и средние рейтинги по каждому параметру.

    3.2. Отображение всех тегов преподавателя.

    3.3. Если пользователь уже оставлял отзыв — он показывается отдельным блоком сверху + кнопка удаления (иначе — «вы не оставляли отзыв» + кнопка перехода на страницу оценивания).

    3.3.1. Удаление отзыва — через модальное подтверждение.

    3.3.2. Оставлять отзыв может только авторизованный пользователь.

    3.3.3. Пользователь не может оставить больше одного отзыва для одного и того же преподавателя.

    3.3.4. Пользователь может отредактировать свой отзыв.

    3.3.5. Администратор не может оставлять свои отзывы, но может удалить любой из отзывов пользователей.

    3.4. Список текстовых отзывов с оценками и датой публикации.

    3.4.1. Сортировка отзывов по дате (новые выше).

    3.4.2. На странице до 10 отзывов.

    3.4.3. Пагинация результатов аналогична главной странице

## 4. Страница оценивания

    4.1. Поля: выпадающий список ФИО/табельного (с поиском; при переходе со страницы отзывов подставляется автоматически), год обучения у преподавателя, предмет, текстовый комментарий, оценки по параметрам (общее впечатление, сложность, интересность, организованность, справедливость) с подписями шкал (например: легко - тяжело, неинтересно - интересно).

    4.1.1. Комментарий может содержать 0–2000 символов.

    4.2. Возможность добавить теги (выбрать существующие или создать новый).

    4.2.1. На теги накладываются ограничения: 1–32 символа, латиница/кириллица/цифры/«-»/«_», нижний регистр.

    4.3. Кнопка публикации. После отправки — редирект на страницу отзывов, где собственный отзыв кратко подсвечивается.

## 5. Страницы регистрации и авторизации

    5.1. Форма регистрации содержит поля: email, пароль, повторение пароля.

    5.1.1. Для верификации почты отправляется ссылка с подтверждением на нее.

    5.1.2. Требования к паролю пользователя: 6-32 символа; разрешены только числа, латиница и специальные символы.

    5.2. Форма авторизации содержит поля: email, пароль.

    5.3. Обе страница имеют кнопки для перехода друг на друга.

## 6. Страница с дашбордами

    6.1. Cтатистика по оцениваниям преподавателей, по динамике отзывов, по частоте использования тегов, по регистрации новых пользователей, по активности пользователей.

    6.1.1. Возможоность выбрать временной промежуток статистики: за день, за месяц, за все время.

    6.2. Логи добавления новых преподавателей и обновлениях старых.

    6.3. Логи удаленных отзывов. 
    
    6.3.1. Рядом с удаленным отзывом должна быть кнопка для бана пользователя.

# Прецеденты использования (Use Cases)

**Акторы:** Пользователь, Администратор.

1. **Поиск преподавателя по ФИО**

   * Триггер: пользователь вводит часть ФИО.
   * Основной поток: запрос → результаты (карточки) → переход к отзывам.
   * Альтернативы: ничего не найдено → показать подсказки/смежные результаты.

2. **Фильтрация по тегам**

   * Триггер: выбор/удаление тегов.
   * Основной поток: обновление списка с учётом выбранных тегов, счётчики рядом с тегами.

3. **Просмотр профиля преподавателя**

   * Триггер: клик по карточке.
   * Основной поток: фото, ФИО, средние оценки, теги, отзывы (пагинация).

4. **Добавление отзыва**

   * Триггер: переход на страницу оценивания.
   * Основной поток: заполнение формы → публикация → редирект → подсветка нового отзыва.
   * Исключения: не заполнены обязательные поля → ошибки валидации; лимит частоты публикаций.

5. **Удаление собственного отзыва**

   * Триггер: нажата «Удалить» → подтверждение.
   * Основной поток: отзыв помечается удалённым, виден баннер «отзыв удалён».

6. **Создание нового тега**

   * Триггер: пользователь вводит новый тег в поле тегов.
   * Основной поток: валидация (длина/дубликаты) → создание → привязка к отзыву.
   * Исключения: невалиднный тег.

8. **Аналитика**

   * Триггер: админ открывает дашборд.
   * Основной поток: статистики, логи.

# Архитектура системы

Компоненты (логический уровень):

* **Data Ingestion (Scraper/ETL на Django):** периодические джобы для сбора ФИО/табельных/фото из открытых источников. Реализация как `manage.py`-команды/скрипты Scrapy, запуск по расписанию через **Celery Beat**. Нормализация данных и запись в PostgreSQL. Хранение фотографий — локально или S3-совместимое хранилище.

* **Core API (Django REST Framework):** REST-эндпойнты для поиска, фильтрации, CRUD отзывов/тегов, агрегаций рейтингов. Аутентификация: сессии или JWT (напр. `djangorestframework-simplejwt`). Пагинация/фильтры — `django-filter`. Ограничение частоты — `django-ratelimit`.

* **Frontend (Vue 3 SPA):** Vite + Vue Router + Pinia. Взаимодействие с API через `axios`. Рендер страниц: «Главная», «Поиск», «Отзывы», «Оценивание», «Дашборды».

* **DB (PostgreSQL):** основное хранилище. Индексы под поиск по ФИО и фильтрацию по тегам; полнотекстовый поиск/`pg_trgm` для частичных совпадений.

* **Админка:** **Django Admin** для просмотра статистик/логов, управление пользователями.

> [!IMPORTANT]
> пока под вопросом:
>    * **Кэш/Очереди (Redis):** кэш популярных запросов/счётчиков тегов/сессий; брокер + бэкенд для **Celery** (пересчёты средних, дедуп тегов, фоновые очистки).
>    * **Деплой/Сетевое окружение:** Nginx раздаёт SPA и проксирует `/api/` на Gunicorn (Django). CORS настроен на домен фронтенда. Логи/метрики централизованы.

Упрощённая схема потока:

```
[Источники ИТМО]
       │
       ▼
[Scraper/ETL (Django mgmt + Celery Beat)]
       │
       ▼
[PostgreSQL] ⇄ [Django + DRF API] ⇄ [Vue 3 SPA]
       │                 │
       └──────⇄ [Redis (кэш)] ⇄──────┘
                         │
                    [Celery воркеры]
                         │
                 [Django Admin (модерация)]
```
